# 鉴权与安全

## 1. 曾经的洞（已补，记录在案）

`officer-agent` 3071 原来 **bind 在 `0.0.0.0`**，而 `/api/action/confirm` **没有任何鉴权**——内网任何人只要能连上这个端口，POST 一个 7 位随机 id 就能触发 agent 已提议的写操作，**包括往政府 rd-web 平台推送合同**。

## 2. 现在的鉴权体系（`src/auth.ts`）

参考 Google API 的做法，但存储上更严（Google 存明文 key，我们只存 hash）。

### 两条身份通道

**① 可信反代**（人在 PMS 里用）

```
浏览器 → PMS(1573) 已验登录态 → 反代时带两个头 → agent 盒子
         X-Proxy-Secret: <共享密钥>
         X-Proxy-User:   <URL编码的登录人>
```

- 共享密钥：`~/pms/.officer_proxy_secret`（600），容器内只读挂载到 `/run/proxy_secret`
- PMS 按登录人路由到各自盒子（`_OFFICER_BOXES`），没盒子的账号 403
- **坑：HTTP 头只能 ASCII，中文用户名必须 URL 编码传**（PMS 侧 `quote()` / agent 侧 `decodeURIComponent()`），否则对面收到乱码

**② API Key**（外部系统接入，如后续的 OPMS）

三种传法都收，与 Google 习惯一致：

```bash
curl -H "Authorization: Bearer oa_xxx" ...
curl -H "X-Api-Key: oa_xxx" ...
curl "...?key=oa_xxx"          # 会进访问日志，慎用
```

### scope 权限位

| 位 | 能干什么 |
|---|---|
| `read` | 看页面、查记忆、看待确认队列 |
| `chat` | 对话 |
| `action` | **执行写操作**（`/api/action/confirm`） |
| `admin` | 管理 API Key |

401 = 没身份/身份无效；403 = 有身份但权限位不够。

### Key 管理

```bash
# 列出（需 admin 位）
curl -H "Authorization: Bearer <admin_key>" 127.0.0.1:3071/api/keys
# 新建，明文只返回这一次
curl -X POST -H "Authorization: Bearer <admin_key>" -H "Content-Type: application/json" \
     -d '{"owner":"OPMS","scopes":["read","chat"],"note":"OPMS 接入"}' \
     127.0.0.1:3071/api/keys
# 吊销
curl -X DELETE -H "Authorization: Bearer <admin_key>" 127.0.0.1:3071/api/keys/<id>
```

- key 格式 `oa_<id>_<random>`，**库里只存 sha256**，明文丢了只能重发
- 首次启动自动生成一把管理 key，打在 `docker logs`（**记得轮换**）
- 存储：`/data/apikeys.json`

### 限流与审计

- 每身份每分钟 120 次（env `RATE_LIMIT_PER_MIN`），超了 429
- 审计日志 `/data/audit.log`，每行一条 JSON：`{ts, who, method, path, status, ip}`
- 写操作额外打一行 `[audit] <谁> 执行了写操作 <id>`

## 3. 端口收口

| 服务 | 监听 | 说明 |
|---|---|---|
| `officer-agent` / `officer-zyj` | **127.0.0.1** | 局域网直连不通，只能经 PMS 反代 |
| `pms-agent`（旧牛马） | 0.0.0.0:3070 | 尚未收口 |
| PMS | 0.0.0.0:1573 | 有登录鉴权 + 滑块 |

`/healthz` 保持开放（给监控用）。**注意路由顺序**：healthz 必须注册在 `app.use(requireScope("read"), static)` **之前**，否则会被静态中间件的权限位抢先返回 403。

## 4. PMS 自身的安全机制（既有）

- **登录滑块**：captcha-svc(3060)，反机器人轨迹校验。紧急关闭 `PMS_CAPTCHA_ON=0`
- **service 账号免滑块**：只对 `PMS_AGENT_USERS` 里的账号 + 来自内网 + **密码仍必须正确**。停用账号即整体吊销该盒子
- **投标文件审核收权**：只给「黄新博」用户名白名单（`BID_REVIEW_USERS`），前端三处隐藏 + 后端 403
- 密码哈希：`pbkdf2_hmac("sha256", pw, salt, 200000)`

## 5. 给外部系统（OPMS）接入的建议路径

1. 用 admin key 建一把专属 key：`owner=OPMS`，scopes 按需（一般 `read`+`chat`，**不给 `action`**）
2. 走 PMS 侧做反代对外暴露（agent 盒子本身不出内网），或在网关 8088 上加一条路由
3. 公网暴露前必做：HTTPS（走现有 cloudflared 隧道）、按 key 限流、审计日志留存、key 定期轮换
4. 写操作**不要**直接给外部 key，让它走"提议 → 人确认"的同一条闸门
