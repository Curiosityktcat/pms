# 运维手册

## 1. 接入

```bash
ssh huangxb@172.1.14.12          # 免密已配
echo <sudo密码> | sudo -S <命令>  # 非交互 sudo；密码不写在文档里，见密码本
```

> **绝不能 `systemctl restart ttyd`** —— 它的 `KillMode=control-group` 会连带杀掉里面常年挂着的 screen 会话。

## 2. 各服务的重启方式（改代码后）

| 类型 | 命令 | 注意 |
|---|---|---|
| PMS 后端 | `sudo systemctl restart pms.service` | 改后端 py 必须重启 |
| PMS 前端 | `bash -lc "cd ~/pms/frontend && npm run build"` | **不用重启服务**，Flask 直接吐 dist；npm 不在非交互 PATH，必须 `bash -lc` |
| 宿主 Python 服务 | `sudo systemctl restart paddle-ocr ocr-multi okf-kb` | — |
| compose 容器 | `cd ~/platform && docker compose build <名> && docker compose up -d <名>` | **只 restart 不换镜像层** |
| agent 盒子 | `bash /tmp/deploy_box.sh …`（内部 `rm -f` + `run`） | 同上 |

> **最常踩的坑**：改了代码 `docker restart`，然后发现没生效——容器绑定的是创建时的镜像 ID，必须重建容器。

## 3. 备份

改动前的习惯做法（本项目一直这么干）：

```bash
cp app.py app.py.bak.<改动名>          # 代码
cp ~/pms/pms.db /tmp/pms.db.bak.<日期>  # 数据库
```

现有备份后缀示例：`.bak.agentauth`、`.bak.agents`、`.bak.niuma`、`.bak.theme`、`.bak.captcha`、`.bak.vlex`。

## 4. 日常巡检

```bash
# 一眼看全（内网总台）
curl -s 127.0.0.1:9099/api/status | python3 -m json.tool | head -40

# 分层看
systemctl is-active pms paddle-ocr ocr-multi okf-kb bge-m3 ops-console
docker ps --format '{{.Names}}\t{{.Status}}'
nvidia-smi --query-gpu=name,memory.used,utilization.gpu --format=csv
uptime                                   # load 长期 20+ 是 ccgp 在跑，正常
```

## 5. 排障速查

| 症状 | 查什么 |
|---|---|
| 网页终端刷屏乱码 | 鼠标追踪模式残留，`screen -S pms -X stuff '^U^Creset\015'`，**别重启 ttyd** |
| OCR 很慢 | ccgp 在抢 CPU，看 `systemctl show ccgp@ocr -p CPUQuotaPerSecUSec` |
| OCR 500 显存错 | `nvidia-smi` 看占用，确认没有第二份 VL 模型被加载 |
| agent 报 PMS 401 | `PMS_AGENT_USER` 与密码文件是否匹配；账号是否在免滑块白名单 |
| agent 流式报错 | llm-gateway 的 SSE 补丁是否还在（容器被 recreate 会丢） |
| LLM 调用不计费 | 是不是绕过了 llm-gateway 直连模型厂商 |
| 归档分类不准 | 看 `/extract` 返回的 `source`：是不是误走了「pdf文本直取」只拿到水印 |

## 6. 关机与重启

所有监听端口的服务都已 systemd `enabled`，19 个容器 `restart=unless-stopped`，**开机全自恢复，无需手动拉起**。

`ccgp` 是唯一没有端口所以扫端口会漏的，已收编为模板单元 `ccgp@.service`，6 个实例均 enabled。
