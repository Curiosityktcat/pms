# 企业微信接入（wecom-agent）

把「牛马」经办人 agent 接到企业微信自建应用上。手机上就能问项目、收催办、丢文件。

## 一句话架构

```
企业微信 App
   │  (成员发消息)
   ▼
企微服务器  ──POST 加密回调──►  https://wecom.curiosityktcat.cn/wecom/callback
                                          │  cloudflared 隧道
                                          ▼
                              wecom-agent 容器 (3080)
                                 │  ①校验签名+AES解密
                                 │  ②查白名单：企微userid → PMS用户
                                 │  ③立即空串回包（企微要求 5 秒内）
                                 ▼
                    officer-agent「牛马」(3071, gVisor 沙箱)
                                 │  PMS 工具 / 法规RAG / shell
                                 ▼
                    算完 → 用「应用消息 API」主动把答复发回企微
```

文件消息则走另一条：`media/get` 取回文件 → `doc-intake(9080)` OCR+判类+归档 → 结果发回企微。

## 能干什么

| 能力 | 怎么用 |
| --- | --- |
| 对话 | 在企微应用里直接说话，等同 PMS 网页版牛马（查项目/进度/合同/过程监督/法规） |
| 主动提醒 | 工作日 `REMIND_AT`（默认 08:30）推：今天要处理的事、卡滞最久的三个项目、待你确认的公告与采购结果 |
| 发文件处理 | 直接把文件/图片发给应用 → OCR + 判类 + 自动归档，结果回消息 |
| 日报/周报 | `REPORT_DOW`+`REPORT_AT`（默认周五 17:00）推一份 HTML 汇报链接 |

## 安全边界（换了入口也不放宽）

- **白名单硬绑定**：`WECOM_USER_MAP` 把企微 userid 映射到 PMS 用户；不在表里的人发消息一律拒绝并记日志。
  牛马以被映射的那个 PMS 身份查数据，**看不到别人的项目**（PMS 侧行级权限照旧生效）。
- **写操作绝不在微信里执行**：牛马只能「提议」，确认动作必须回 PMS 网页点。这条是设计，不是限制没做完。
- 回调必须过企微签名校验 + AES 解密；同一 MsgId 5 分钟内只处理一次（企微会重推）。
- 3080 只绑 `127.0.0.1`，公网只能经 cloudflared 打到 `/wecom/callback`。

## 开通步骤（一次性）

1. **企微后台建自建应用**：管理后台 → 应用管理 → 自建 → 创建应用（可见范围先只加自己）。
   记下 **AgentId** 和 **Secret**；**CorpID** 在「我的企业」页。
2. **填凭据**：编辑 `~/platform/services/wecom-agent/.env`（照 `.env.example`），
   `WECOM_USER_MAP` 里的 userid 是**成员的「账号」字段**（通讯录点开成员能看到），不是姓名也不是手机号。
3. **开公网入口**：`sudo bash ~/apply_wecom.sh`
   （加 cloudflared ingress → 建 DNS → 重启隧道 → 重新部署容器 → 自检）。
4. **企微后台设接收消息**：应用详情 → 接收消息 → 设置API接收：
   - URL：`https://wecom.curiosityktcat.cn/wecom/callback`
   - Token / EncodingAESKey：与 `.env` 里的 `WECOM_TOKEN` / `WECOM_AES_KEY` 一致
   - 点保存，企微会立刻来校验，**通过即接通**。
5. **企业可信IP**：应用详情 → 企业可信IP，加上本机出口公网 IP（当前是 `117.139.127.146`，
   家宽会变，**发消息报 `not allow to access from your ip` 就是它变了**，回来改这里）。

## 排障

| 症状 | 多半是 |
| --- | --- |
| 企微后台保存回调地址报「回调失败」 | Token/AESKey 与 `.env` 不一致；或 cloudflared 没起（`curl https://wecom.curiosityktcat.cn/wecom/callback` 应返回 401 而不是超时） |
| 能收到消息但没有答复 | 发消息 API 被拦：看 `docker logs wecom-agent`，多半是**企业可信IP** 没加或家宽 IP 变了 |
| 答复是乱码 | 已修（SSE 响应无 charset，requests 默认按 ISO-8859-1 解码），若复发检查 `resp.encoding = "utf-8"` 那行 |
| 报 `connection refused` 连 officer-agent | 两个容器必须在**创建时**就 `--network agent-net`；gVisor 下事后 `docker network connect` 加的网卡，已监听的 socket 收不到连接 |
| 未授权的人也能用 | 检查 `WECOM_USER_MAP`，以及应用的「可见范围」 |

## 自检手段（不需要真企微）

- `curl 127.0.0.1:3080/healthz` → `configured` 为 true 表示凭据齐、加解密初始化成功。
- `curl -XPOST 127.0.0.1:3080/ask -d '{"text":"..."}'` → 直接拿牛马的答复（绕过微信，验证内部链路）。
- `curl -XPOST 127.0.0.1:3080/push -d '{"kind":"remind"}'` → 立刻触发一次提醒推送。
- 加密回调全链路自测脚本：`~/pms/venv/bin/python /tmp/wecom_selftest.py`（自己扮演企微服务器发加密报文）。
