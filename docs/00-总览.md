# 系统总览

> 面向**接手开发的人**：读完这一篇，你应该知道这台机器上有什么、彼此怎么依赖、改一处会影响谁。

## 1. 这是什么

内江市第一人民医院政府采购业务的一套自建系统，跑在一台服务器上（内网 `172.1.14.12`，主机名 `huangxb-Default-001`，Ubuntu 24.04，36 核 / 62G 内存 / 1.9T）。

核心是 **PMS 采购管理系统**（招标采购全流程），围绕它长出了 OCR、智能归档、AI 助理、法规检索等能力。

## 2. 硬件与显卡分工

| 部件 | 型号 | 干什么 |
|---|---|---|
| GPU 0 | Tesla V100-SXM2-16GB（`06:00.0`，CUDA） | PaddleOCR-VL 全部 OCR |
| GPU 1 | Radeon RX 7900XTX（`05:00.0`，ROCm，主显） | 本地大模型 Qwen3.6-27B |
| CPU | Xeon E5-2686 v4 ×2，36 线程 | 其余全部服务 |

> **注意**：V100 的 PCIe 链路是 `x2`（转接板只通 2 条 lane，`LnkCap x16 / LnkSta x2`）。实测对 OCR 影响约 2%，不必处理；但如果将来跑大批量数据搬运会成为瓶颈。卡本身健康（fp16 算力 87.6 TFLOPS，零 replay、零 AER 错误）。

## 4. 依赖关系（改动前先看这张图）

```
浏览器
  │
  ├─ PMS (1573) ──┬─→ officer-agent (3071/3072)  AI 助理，按登录人分流
  │               ├─→ doc-intake (9080)          资料归档（同源反代）
  │               ├─→ captcha-svc (3060)         登录滑块
  │               └─→ bid-review (9010)          投标审核
  │
  └─ 总台 (9099) ──→ 各服务导航

doc-intake (9080) ─→ paddle-ocr (8118)   OCR 取字
                  ├─→ llm-gateway (8600) 判类抽字段
                  └─→ pms-agent (3070)   归档到采购项目后移交研判

officer-agent ────┬─→ llm-gateway (8600) 大脑
                  ├─→ PMS (1573)         查项目/提议写操作
                  ├─→ okf-kb (5001)      法规检索
                  └─→ doc-intake (9080)  读文档取文本

llm-gateway (8600) ─┬─→ DeepSeek（云）
                    ├─→ agnesai / Gemini（云）
                    └─→ llama-server (8080) 本地 Qwen（数据不出内网）

ocr-multi (8119) ──→ paddle-ocr (8118)   复用常驻 VL，不重复加载模型
```

**几条硬性依赖，改动时务必留意：**

1. **所有 LLM 调用必须走 `llm-gateway:8600`**，不要直连 DeepSeek。网关负责多模型路由、`tools` 透传、流式 SSE、以及**统一计费记账**（`/usage`）。绕过网关 = 这笔花销记不上账。
2. **OCR 只有 8118 一个进程持有 VL 模型**（约 8.5G 显存）。任何服务要 OCR 一律 HTTP 调它，**绝不要在别处再 `PaddleOCRVL()` 一次**，16G 单卡会 OOM。
3. **PMS 是唯一的业务数据真源**（`~/pms/pms.db`）。agent、归档、审核这些服务都只是它的外围，不要另建一份项目台账。

## 6. 接手第一步做什么

```bash
ssh huangxb@172.1.14.12          # 已配免密
sudo -S                          # 密码见运维手册（不写在文档里）

systemctl list-units 'pms*' 'ocr*' 'paddle*' 'okf*'   # 宿主服务
docker ps --format '{{.Names}}\t{{.Status}}\t{{.Ports}}'  # 容器
curl -s 127.0.0.1:9099/api/status | head              # 总台聚合状态
```

先把《运维手册》通读一遍，再按需要看各模块分册。
