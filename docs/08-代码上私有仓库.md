# 代码上私有仓库

目的：**以后新客户能一条命令部署，不用每台机器手工调。** 顺带解决备份问题 ——
现在代码只躺在 .12 上，那台机器硬盘坏了就全没了。

---

## 一、先纠正一件事：不是「建三个库」

「代码库、数据库、私钥库分离」这个方向是对的，但**分离不等于都用 git**。
三样东西的性质完全不同：

| | 放哪儿 | 为什么 |
|---|---|---|
| **代码** | Git 私有仓库 | 要历史、要回滚、要对比。这是 git 唯一擅长的事 |
| **数据库** | **不进 git**，定期备份到独立位置 | 二进制、几百 MB、每天都变。进 git 会让仓库爆炸，而且 git 帮不了你恢复到「昨天下午三点」 |
| **密钥** | **不进 git**，独立发放 | git 里删掉的东西**历史里还在**。密钥一旦进过 git，就得当它已经泄露 |

所以实际上是：**git 里只有代码 + 配置模板**，数据和密钥各走各的路。

> **一句话记住**：git 是「谁在什么时候改了哪一行」的账本，
> 不是网盘，也不是保险箱。

---

## 二、建几个仓库

**一个系统一个仓库**，共 5 个（按需要陆续建，不用一次建完）：

| 仓库名 | 放什么 | 现在的位置 |
|---|---|---|
| `opms` | 代理公司项目管理系统 | `.12:~/opms` |
| `pms` | 医院采购管理系统 | `.12:~/pms` |
| `cga` | CGA 系统 | `.12:~/cga` |
| `okf-kb` | RAG 知识库 | `.12:~/okf-kb` |
| `platform` | 容器平台（网关、各微服务） | `.12:~/platform` |

**全部选 Private。**

再加一个可选的第 6 个：

| `deploy` | 各系统的 docker-compose、部署脚本、`.env.example` 模板 | 现在散在各处 |

它的用处是「新客户装机」：clone 这一个仓库就知道要装什么、要配哪些项。
不急，等前面几个推完再说。

**不要建的仓库**：`opms-data`、`opms-secrets` 这类。理由见上一节。

## 三、密钥怎么管

### 原则

1. **代码里永远不写真密钥**，只写「从哪里读」。
   现在 `start.sh` 写的是 `SECRET="$(cat .secret)"` —— 这就是对的。
2. 仓库里放一份 **`.env.example`**，列出要配哪些项，值全部留空或写假值。
3. 真密钥放在**每台机器自己的** `.env` 文件里，`.gitignore` 忽略它。

### `.env.example` 长什么样

OPMS 的那份已经写好了，在 `~/opms/.env.example`，长这样（节选）：

```bash
# 复制成 .env 再填真值。.env 不进仓库。
OPMS_SECRET=            # 会话签名密钥，换了它所有人要重新登录
                        # 生成：python3 -c "import secrets;print(secrets.token_urlsafe(48))"
OPMS_DB=/data/opms.db
OPMS_UPLOADS=/data/uploads
OPMS_COOKIE_SECURE=0    # 公网部署一定要设 1
OPMS_LLM=               # 大模型网关地址
OPMS_CAPTCHA_URL=       # 滑块验证服务
# 下面这些只在开发机上设，**生产设了等于开后门**：
# OPMS_SMOKE_KEY=       # 自动化测试跳过登录用
```

别的系统照这个样子各写一份。

### 真密钥放哪儿

**小团队（你现在这样）**：每台机器上一个 `.env` 文件，权限设 600，
另外把一份抄在密码管理器里（Bitwarden、1Password、KeePass 都行）当备份。

**不要**用微信、邮件传密钥 —— 传完就留在聊天记录里了。

### 万一密钥进过 git

当它已经泄露，**去把那个密钥换掉**，不要指望「删掉那次提交」。
git 的历史是可以被 clone 走的，你不知道谁已经拿到了。

## 四、数据库怎么管

**不进 git。** 走备份，而且备份要满足两条：

1. **异地** —— 备份不能和数据库在同一台机器上。.12 挂了，备份也得还在。
2. **能恢复到某一天** —— 不是只留最新一份。

现在各系统已有的备份脚本（`~/opms/backup.sh` 那类）继续用，
但要确认备份文件**同步到了另一台机器或网盘**（.12 上有挂载的 Google 网盘可以用）。

数据库文件本身用 `.gitignore` 挡住，各仓库里都已经写了：

```gitignore
*.db
*.db-wal
*.db-shm
uploads/
```

## 五、一步步操作

### 第 1 步：加 SSH 公钥（只做一次）

这样以后所有仓库都不用再传 token。

在 .12 上看公钥：

```bash
cat ~/.ssh/id_ed25519.pub
```

把整行复制，到 GitHub：**右上角头像 → Settings → SSH and GPG keys →
New SSH key** → Title 填 `.12 开发机` → Key 粘贴 → Add SSH key。

验证：

```bash
ssh -T git@github.com
# 看到 "Hi <你的账号>! You've successfully authenticated" 就成了
```

### 第 2 步：在 GitHub 上建空仓库

**New repository** →

- Repository name：`opms`
- **Private 勾上**
- Add a README file：**不勾**
- Add .gitignore：**None**
- Choose a license：**None**

三项都不选，建一个完全空的仓库 —— 本地内容推上去才不会撞。

### 第 3 步：推之前必须先扫一遍

**这一步不能省。** 推上去之后再发现问题，历史里就留下了。

```bash
python3 ~/tools/secret_scan.py ~/opms
```

它扫两样：当前**已提交**的文件、**以及全部 git 历史**。

- 看到「**干净，可以推**」（退出码 0）才能推
- 报出「严重」的先清干净，怎么清见第八节
- 「提示」那一档（内网地址这类）不拦你，知道就行

**注意**：它扫的是已提交的内容。刚改完没 commit，扫了也白扫 ——
脚本会提醒你有几个文件没提交。

**它扫不到二进制**：docx、图片、xlsx 里的内容看不见。
仓库里如果有客户的扫描件、名册，单独确认一遍。

### 第 4 步：推

```bash
cd ~/opms
git branch -M main
git remote add origin git@github.com:<你的账号>/opms.git
git push -u origin main
```

### 第 5 步：以后日常怎么用

```bash
cd ~/opms
git add -A
git commit -m "改了什么"
git push
```

在另一台机器上取：

```bash
git clone git@github.com:<你的账号>/opms.git
cd opms
cp .env.example .env    # 然后填真值
```

## 六、新客户装机时怎么用这套

```bash
# 1. 取代码
git clone git@github.com:<账号>/opms.git
cd opms

# 2. 配这台机器自己的密钥
cp .env.example .env
vi .env                    # 填真值

# 3. 起服务（数据库会自动建，是空库）
docker compose up -d
```

**新客户是空库**，不要把别家客户的数据库拷过去 ——
里面有别人的项目、专家、采购人档案。

存量模板导入也是同理：`backend/import_rules.example.json` 复制成
`import_rules.json`，按这家机构的名称、邮箱、电话、地址改一遍。

## 七、推之前的检查清单

逐条过，全部打勾才推：

- [ ] `.gitignore` 里有 `*.db`、`uploads/`、`.env`、`.secret`
- [ ] `git ls-files | grep -E '\.db$|uploads/|\.env$'` 输出为空
- [ ] 扫描脚本报「干净」（**当前文件和历史都要干净**）
- [ ] 代码里没有客户单位真名、真人姓名、真实电话邮箱地址
- [ ] 演示数据（seed）里的单位名是虚构的 —— 新客户装上不该看见别家的名字
- [ ] 测试脚本里没写死真人姓名
- [ ] 仓库是 **Private**

> **最容易漏的三处**（都是真踩到的）：
> ① **代码注释**里拿真实客户数据举例（真人姓名、真手机号）——
>    没人会想到注释里有个人信息；
> ② **出厂模板 .docx** 里残留的客户地址 —— 扫描器看不见 docx 内容，
>    只能打开翻一遍；
> ③ **docker-compose.yml 里写死的密码** —— 变量名叫 `MAIL_PASS`、`SMTP_PASS`，
>    扫描器原来只认 `password`/`passwd`，正好漏过去。已经补上
>    （`pass`/`pwd`/`credential` 都认），但这说明**扫描器报干净不等于真干净**，
>    配置文件还是要自己翻一遍。

## 八、历史里已经有脏东西怎么办

文件现在删了没用，**历史里还在**，clone 一份就全带走。必须重写历史。

工具：`git-filter-repo`（装在各项目的 venv 里）

```bash
# 先备份！
cd ~ && tar czf /tmp/xxx-backup.tgz --exclude=venv --exclude='*.db*' xxx

# 文本替换（客户名、邮箱、电话这类）
cat > /tmp/replace.txt <<'EOF'
真实医院名==>虚构医院名
真实邮箱@xx.com==>demo@example.com
EOF
cd ~/xxx && venv/bin/git-filter-repo --replace-text /tmp/replace.txt --force

# 整个文件从历史里摘掉（图片、身份证扫描件这类二进制）
venv/bin/git-filter-repo --path 那个目录/ --invert-paths --force
```

**两个要点**：

1. **文本替换对 .docx / 图片无效** —— docx 是压缩包，里面的内容 filter-repo 看不见。
   二进制文件里的敏感内容只能用 `--path` 整个摘掉。
2. **洗完必须重新跑一遍测试。** 替换是全局的，可能误伤代码里的断言字符串
   （真发生过：把断言里的机构名也改了，导致断言和实际数据对不上）。

洗完再扫一遍，确认为 0 才推。
